# @github-reskin/primer

The Primer adapter for renderer 1. It turns GitHub's frozen mode stylesheets into `ModeSeed` records, picks the seed for a page's GitHub mode, and compiles a resolved theme into the stylesheet GitHub reads. Pure and deterministic: no DOM, storage or network. Runtime modules import the frozen data; the engine never does.

| Export | Behavior |
| --- | --- |
| `selectMode(native, base, index)` | `ModePlan` for a `NativeMode` and theme base. Standard modes (light, dark, dimmed) use the standard seed of the theme's base; colorblind and tritanopia use their own family's seed and carry `GitHub accessibility colors are active`; every high-contrast mode returns `native-high-contrast`; an unknown mode or missing counterpart returns `native-unknown`. |
| `seedFor(index, plan)`, `standardSeed(index, base)` | The seed to pass as `ResolveContext.seed`, and the standard seed `repairTheme` needs. |
| `compileGitHub(resolved, plan, prefs, index?, options?)` | `CompiledStyle`. Native, forced-color and disabled inputs give empty CSS. Themed output is the family seed's native baseline, then every variable in `mappings.json` from its resolved role, scoped to the GitHub mode islands the plan covers, inside `not (forced-colors: active)`. `index` defaults to the frozen production index. `options.selection: false` leaves the browser's own selection colors in every engine; the content adapter's `compileOptions(document)` gives it on pages of `LARGE_PAGE_ELEMENTS` (10,000) elements or more. |
| `modeSelectors()`, `scopeSelectors(modes)` | GitHub's own island selectors per reviewed mode, mirrored exactly and checked against the frozen files. |
| `islandScope(covered, known, baseOf, branch)`, `BRAND_FOOTER` | The compiler's island selectors for one color-scheme branch: unsafe boundaries, eligible, themed and native islands, and the nearest-island helper for rules that are not inherited. |
| `MODE_INDEX`, `MODE_POLICY`, `NOTICES` | The deep-frozen `vendor/primer/modes.json`, the reviewed policy and the plan notices. |

Files:

- `mode-policy.json`: every reviewed GitHub mode with its base, family, high-contrast flag and policy, plus each family's seed per base. A mode missing here blocks `scripts/refresh-primer.mjs --accept`.
- `mappings.json`: the maintained table. `seed` names the upstream variable for every `ColorSet` leaf and the opaque role a translucent value is flattened over. `emit` names every GitHub variable the compiler writes and its role, or why it is exempt from pair checks. `rolePairs` lists the C2 pair-matrix IDs covering each role. `inheritedPairs` lists foreground and background variables GitHub's own stylesheets paint together that the matrix does not name. `readableWith` and `readableOn` fall back to another resolved role, with a warning, where one of those pairings would not read. `brandFooter` maps the Primer Brand footer variables.
- `css.js`, `convert.js`, `generate.mjs`: the offline parser and converter. `node packages/primer/generate.mjs` rewrites `vendor/primer/modes.json` and `provenance.json` from `vendor/primer/source`; `--check` compares instead.
- `checks.mjs`: `check:primer` and `check:slot-contracts`.

Refreshing upstream data is a separate maintenance step: `node scripts/refresh-primer.mjs` downloads into a temporary directory and prints the delta; `--accept <dir>` freezes that reviewed download. No build or check fetches anything.

Nested islands: GitHub declares all of its mode variables on every element carrying a known mode, so an island of a high-contrast or other-family mode resets every variable the compiler writes. The compiler writes only variables every frozen mode declares.

An island whose native reset cannot be proved is unsafe: an unknown mode, a color mode without the theme attribute it reads, a stray value, or any island without theme attributes, empty and text-only ones included, other than the Primer Brand footer's. That footer is recognized only in GitHub's structure, `react-partial[partial-name="marketing-footer"] > div > [data-color-mode]` around `footer[role="contentinfo"]`, and that island and the islands without theme attributes inside the footer only with GitHub's `light` or `dark` value; any other value is unsafe. An unsafe island inherits from its nearest island with theme attributes. When that island is themed it is suppressed: it keeps GitHub's own declarations for its mode and clears the Reskin switches. When it is a native island, its reset already protects the unsafe one, and nothing above it is suppressed. Every other island stays themed. The nearest island is found exactly through six islands with theme attributes from the root. A selector cannot name the nearest of any number of ancestors, so a deeper island is suppressed by any unsafe island inside it that no native island past the first six separates from it, and by any unsafe island inside it at all when such a native island is above it. Brand footer variables are not reset by GitHub's mode files, so the footer, and each Brand island in it, keeps GitHub's Brand colors while it holds any island but the plan's and its own light or dark ones: high-contrast, other native, unknown and unsafe islands. A footer that is itself an island takes the Brand mapping only through its own themed mode. Each suppression depth is a `:has()` on the islands themselves, so browsers without `:has()` drop the themed rules and stay native.

In Chromium each `:has()` walks the subtree it is anchored on after a DOM change below it. The compiler anchors them on islands and, for selection, once on the body. On the reference M1 Max, an append, remove and style flush takes 0.7 ms p95 on a 2,800-element page and 2.6 ms at 20,000 elements with a themed root, and 0.1 ms when the root is suppressed.

Rules that are not inherited custom properties (activity overview shape, commit-share bars, issue labels, Brand footer, selection) follow the nearest island, the native island itself included, and a themed island nested in a native one starts again. Eligible islands set the inherited `--reskin-on` switch and every other island with theme attributes clears it. A graph or label that is itself an island follows its own mode. For other subjects every engine reads the switch with a container style query, which reads the parent's, so nesting depth does not matter. Gecko before Firefox 151 has no style queries and matches selectors instead: exactly through six islands with theme attributes from the root, so a standard island inside a native or suppressed one is themed again. Deeper, a subject is themed while the islands above it form at most three runs of themed and native islands, ending themed, and no themed island past the first six above it could be suppressed. Other deep subjects keep GitHub's styles there.

Gecko from Firefox 151 has style queries and skips the selector fallback, which is gated on `position-anchor: normal`, first accepted in the same release. In the fallback, Gecko tests a nested rule's parent against every element, so the parent names the subjects first. No other rule nests, and each subject alternative leads with its own class, element or attribute, so engines test it only against those elements.

Protected UI, the registry's `PROTECTED` list and the `data-reskin-protected` marker, keeps GitHub's own components and colors. Every form is protected, whatever its action. Every structured rule refuses protected UI and everything inside it; no island on or inside it, nor an island past the sixth from the root that holds it, takes the theme or raises the switch; and a final rule clears the Reskin switches on it, as a native island does. Protected UI that is not an island itself takes back its nearest island's own native values, from `restoreCss` in the ModeIndex: each themable mode's value of every variable a themed island writes, with its color scheme. Every covered island names its mode in `--reskin-mode`, which engines with container style queries read with the switch. Gecko before Firefox 151 finds a plan island nearest by selector through six islands and takes back GitHub's own values for the seed's mode: exact in an island of that mode, and GitHub's colors of the seed's mode in the plan's other modes, since every mode's own values there would add about 130 KB to the stylesheet. Brand variables on a Brand island around protected UI are not restored, since no native Brand values are vendored.

Scrollbar colors inherit, and on a large diff restyling every element with them costs more than a frame. Eligible islands carry them for the viewport, every island's children start again from the browser's at no specificity, and GitHub's scroll containers (`pre`, `.overflow-auto`, `.overflow-x-auto`, `.overflow-y-auto`, `.overflow-scroll`) take them where their nearest island is eligible.

Apply cost (`tests/primer/apply-cost.test.mjs`): inserting the stylesheet into the fixed 10,000-line diff with a full-year graph, about 70,000 elements, and flushing style and layout, compiled with the adapter's options for that page, so without selection. A stylesheet that sets one root variable is the control, since any root variable restyles every element. With selection, Chromium spends about 30 ms more there on the `::selection` rule, which it follows into every element. The test also records C5's resolve, compile and mount path for Choom Circuit on the same page. On the shared M1 Max on 2026-11-09, at load averages of 33 to 43, Chromium 156 took 52.7 ms in Full and 51.4 ms in Calm against a 40.4 ms control, and Firefox 157 49 and 48 ms against 43 ms. Through C5's path Chromium took 89.5 ms against 38.8 ms, about 14 ms of it resolving, and Firefox 65 ms against 42 ms.

Selection: Gecko matches selection per element, so themed islands carry the selection colors in Reskin properties and everything else keeps HighlightText on Highlight. Chromium's selection inherits from the parent, and its own colors cannot be restored once an ancestor has a selection rule. So Chromium themes selection from the body of a themed root, and only while every island on the page is the plan's or the Brand footer's. Otherwise the whole page keeps the browser's selection.
