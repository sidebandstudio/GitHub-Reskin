# @github-reskin/format

Theme format v1 with the Revision 4 expansion. Pure ESM with no DOM, storage, network or code evaluation. The schema is `theme-v1.schema.json`, the reviewed copy published at its `$id`.

Three entries share the same functions:

| Entry | Contents |
| --- | --- |
| `index.js` (`.`) | `viewer.js` plus `authoring.js`. Every existing consumer keeps full behavior. `package.json` marks `index.js` and `authoring.js` as having side effects, so a bundler keeps the sanitizer for named imports from this entry; the engine's `index.js` is marked the same way. |
| `viewer.js` (`./viewer`) | Everything except the CSS parser. CSS and gradientCss admission come from build-time proofs (`registerCssProofs`) or from the sanitizer once `authoring.js` loads; otherwise CSS-bearing themes fail validation with `css-unavailable` instead of rendering. |
| `authoring.js` (`./authoring`) | Installs the css-tree 3.1.0 sanitizer. After it loads, the synchronous calls (`parseImport`, `validateTheme`, `normalizeTheme`, `decodeShare`) behave exactly as in the full entry. |

| Export | Behavior |
| --- | --- |
| `parseImport(input, kind)` | `kind` is `text`, `file` or `code`. Bounds input by UTF-8 bytes (512 KiB file, 768 KiB pasted), decodes bytes as strict UTF-8, strips a BOM, then finds exactly one theme object in plain JSON, JSONC (line comments end at LF, CR or CRLF), a code fence or surrounding prose, or a share code or share link. Returns `{ok:true, source, normalized, notes}` or `{ok:false, issues, candidates?}`. Notes include warnings for requests this increment renders another way (`capabilityNotes`). Never repairs, resolves or saves. |

## Advanced CSS policy in brief

css-tree 3.1.0's published browser bundle, unchanged, with one application-owned grammar (`corner-shape`) added through `fork()`. Parsing uses positions and parsed custom properties; recovery, Raw nodes, bad tokens and unclosed blocks reject. Names are escape-decoded and lowercased before comparison. Only `@media` over reduced motion, hover, pointer and min/max width, and `@supports` whose tests are `(property: value)` declarations of properties a theme may set, with literal values (no `var()`, resources or vendor syntax), alone, after `not`, or joined by one of `and`/`or`; selector, font and other function tests are refused, and css-tree 3.1.0 reads a parenthesized group of conditions only through parse recovery, so groups are refused too. Nesting is a deferred convenience. Selectors: classes, IDs, elements, descendant and child combinators, the state and structural pseudo-classes, bounded `:is/:where/:not`, exact `data-testid`, `data-component`, `data-reskin-slot` and `aria-current` predicates, `::before/::after` only on owned slots. Resources, `attr()`, `counter()`, strings outside empty owned `content`, unknown functions and units, vendor keywords, CSS-wide keywords (`inherit`, `initial`, `unset`, `revert`, `revert-layer`), non-finite numbers and nesting past 8 reject. `calc()`, `min()`, `max()` and `clamp()` must evaluate to a finite, ordered range in one unit, with `clamp()` following CSS (the minimum wins over a smaller maximum). Native properties come from THEME-EXPANSION.md's allowlist; owned decorations add bounded geometry, with a transform of at most one translation followed by at most one rotation and a `transform-origin` only at the center (`center` or `50% 50%`, zero depth), so a rotation never moves the box; only the 404 corner stamp may position itself. Shadows: four entries, blur 0-24px and spread proved from literal lengths (a supplied variable blur or spread rejects), sum 48px, offsets ±8px, spread -8..4px, native alpha 0.8 except the crisp opaque rule (no blur or spread, offsets within 1px, not inset). Backgrounds: four gradient layers, 2-8 color stops with at most two positions, no hints, nondecreasing positions in one unit, bounded positions, angles, radial geometry and repeating periods. Theme-local `--theme-*` variables are declared once outside `@media`/state rules, acyclic, at most eight edges deep counting fallback references, and each a valid color, finite number or length, or audited variable, used or not. Their expanded bytes and nodes are measured from the dependency graph before any expansion is built, so a branching graph fails on its budget without allocating it. They are substituted statically; only the audited `--reskin-*` registry remains. Every `var()` fallback is checked against the property at each use, then removed, including fallbacks inside the theme-local variables a value uses, directly or through other locals: each local carries the values any one of its fallbacks could give it, under its own byte budget, and each use checks them. Budgets: 32 KiB source and expanded output, 256 rules, 512 selectors, 2048 declarations, 20,000 nodes, 32 parts a selector. The canonical output must parse back to itself and the same IR.

## Registry input C3 supplies (`CssTargetRegistry`, `registryVersion: 1`)

Declared in `packages/contracts/index.d.ts`; `tests/fixtures/css-registry-synthetic.json` is a synthetic example used only by tests.

- `kinds`: for each `CSS_TARGET_KINDS` entry used, `{properties, colors, literalColors, blur, textShadow, inheritable, maxTargets}`. `properties` come from the native allowlist; `colors[property]` lists the audited `--reskin-*` variables that property may use; `literalColors` names properties that may take literal colors or gradients (decorative boundaries, verified blank backing); any other color property must name one of its `colors` variables, so a keyword or `none` cannot leave the audited pair; `inheritable` is true only when every subject is a leaf or its whole subtree shares the policy.
- `subjects`: exact signatures `{kind, classes, element?, id?, predicates?, routes}`. A theme compound matches only with exactly these classes; every attribute predicate it uses, including inside `:not()`, must be listed.
- `rootKind`: `"page-backing"` or null, the marked subject html/body/:root map to.
- `invalidation`: the attributes and events that revoke admission before the next styled render.
- `fixtures`: reviewed fixture paths to SHA-256.

The compiler requires `[data-reskin-css="active"]` on the scope, `[data-reskin-css-native="active"]` for native rules, `[data-reskin-css-kind="<kind>"]` on each native subject, and excludes `[data-reskin-native]` and `[data-reskin-protected]` and their descendants. Owned rules target `[data-reskin-owned][data-reskin-slot="<slot>"]`.

`schema-validator.js` and `schema-registry.js` are generated by `node packages/format/generate.mjs`; `check:schema` fails when they differ. `checks.mjs` exports `run({command, args, root, outDir})` for `schema`, `prompt`, `css`, `classic-themes` and `themes`; `css/checks-css.mjs` runs every named case of `tests/fixtures/css-review-r41-cases.json` and `css-policy-cases.json`.
